# ORP

ORP - небольшая CLI-утилита на Go для управления пользовательскими
экземплярами OlcRTC через systemd. Инструмент создает директорию пользователя,
генерирует YAML-конфиг OlcRTC, создает systemd-сервис, запускает его и хранит
сгенерированные данные подключения в `/opt/orp/data/users.json`.

> Статус: ранний прототип. Проект собирается и запускается, но перед
> использованием на публичном или production-сервере нужно закрыть несколько
> важных проблем. Смотри раздел [Критичные слабые места](#критичные-слабые-места).

## Возможности

- Создает пользовательские конфиги OlcRTC в `/opt/olcrtc-users/<username>`.
- Генерирует случайный Jitsi room id и криптографический ключ для пользователя.
- Создает и управляет systemd-сервисами `olcrtc-<username>.service`.
- Хранит данные пользователей и ссылки подключения в `/opt/orp/data/users.json`.
- Позволяет изменить базовый Jitsi-домен в `/opt/orp/config.json`.

## Требования

- Linux-сервер с systemd.
- Root-права для команд, которые пишут в `/opt` и `/etc/systemd/system`.
- Go `1.26.3` или совместимая версия, соответствующая `go.mod`.
- Бинарник OlcRTC по пути:

```bash
/opt/olcrtc/olcrtc-linux-amd64
```

## Сборка

Сборка под текущую платформу:

```bash
go build -o orp .
```

Сборка Linux amd64 бинарника:

```bash
GOOS=linux GOARCH=amd64 go build -o orp-linux-amd64 .
```

## Установка

Пример установки на Linux-сервер:

```bash
sudo install -m 0755 orp-linux-amd64 /usr/local/bin/orp
sudo mkdir -p /opt/orp/data /opt/olcrtc /opt/olcrtc-users
sudo install -m 0755 olcrtc-linux-amd64 /opt/olcrtc/olcrtc-linux-amd64
```

Бинарник OlcRTC не входит в этот репозиторий. Его нужно положить отдельно по
пути `/opt/olcrtc/olcrtc-linux-amd64`.

## Использование

Задать базовый Jitsi-хост:

```bash
sudo orp changebase meet.example.com
```

Создать пользователя и запустить его OlcRTC-сервис:

```bash
sudo orp add alice
```

Показать список пользователей:

```bash
sudo orp list
```

Показать последние логи пользовательского сервиса:

```bash
sudo orp logs alice
```

Удалить сервис и сгенерированную директорию пользователя:

```bash
sudo orp delete alice
```

Команда `restart` сейчас есть в CLI, но в коде она вызывает ту же логику, что и
`add`. До исправления ее лучше не использовать.

## Создаваемые файлы

| Путь | Назначение |
| --- | --- |
| `/opt/orp/config.json` | Глобальный конфиг ORP, сейчас хранит Jitsi-хост. |
| `/opt/orp/data/users.json` | Данные пользователей и ссылки подключения. |
| `/opt/olcrtc-users/<username>/srv_template.yaml` | Пользовательский конфиг OlcRTC. |
| `/etc/systemd/system/olcrtc-<username>.service` | Пользовательский systemd unit. |

## Структура проекта

```text
.
├── main.go
├── cmd/                 # Cobra CLI-команды
├── internal/configs/    # Загрузка и сохранение /opt/orp/config.json
├── internal/storage/    # Загрузка и сохранение /opt/orp/data/users.json
├── internal/systemd/    # systemctl и операции с service-файлами
├── internal/templates/  # Встроенные systemd и OlcRTC шаблоны
└── internal/users/      # create/delete/list/log/restart пользовательских сервисов
```

## Критичные слабые места

Самые важные проблемы, найденные при ревью:

1. Имена пользователей не валидируются и не очищаются. Значение напрямую
   используется в путях файловой системы и именах systemd-сервисов, что может
   привести к path traversal, поломанным unit-файлам или небезопасному удалению.
2. `restart` подключен неправильно. В `cmd/restart.go` вызывается
   `users.CreateUser`, а не `users.Restart`, поэтому команда может попытаться
   пересоздать пользователя.
3. Секреты хранятся слишком открыто. Хэши и полные OlcRTC URL записываются в
   `/opt/orp/data/users.json` с правами `0644`.
4. Частичные ошибки оставляют систему в несогласованном состоянии. Директории,
   service-файлы, enabled-сервисы и JSON-хранилище обновляются по шагам без
   rollback.
5. Часть ошибок игнорируется или обрабатывается через `panic`. Например, ошибка
   генерации room id игнорируется, `storage.Load` скрывает все ошибки чтения, а
   `changebase` падает через `panic` при ошибке загрузки или сохранения конфига.
6. Нет нормальной обработки дубликатов пользователей. `add` падает на создании
   директории, если она уже существует, но CLI не объясняет, что произошло и как
   восстановиться.
7. Help-тексты CLI все еще содержат стандартные заглушки Cobra, поэтому перед
   релизом нужно привести UX команд в порядок.
8. Нет автоматических тестов на безопасность путей, маршрутизацию команд,
   генерацию конфигов, systemd-шаблоны и восстановление после ошибок.

## Рекомендуемый порядок исправлений

1. Добавить валидацию username, например `^[a-zA-Z0-9_-]{1,32}$`, и отклонять
   остальные значения до любых операций с файловой системой или systemd.
2. Исправить `restart`, чтобы команда вызывала `users.Restart` и возвращала
   ошибки через Cobra.
3. Хранить секреты с более строгими правами, например `0600`, и не показывать
   чувствительные значения в `list`, если это не нужно.
4. Сделать `create` и `delete` более транзакционными: при частичной ошибке
   откатывать уже созданные директории, unit-файлы и изменения storage.
5. Заменить шаблонные тексты Cobra на реальные описания и примеры команд.
6. Добавить точечные тесты для username validation, template rendering и command
   dispatch.
